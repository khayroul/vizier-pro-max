# Artifact Quality Overhaul v2

**Date:** 2 April 2026
**Status:** Design approved, pending implementation
**Approach:** B — Pipeline rewrite with visual layer, C-ready hooks for future brand config / A-B variants

## Context

Benchmark outputs from all 5 pipelines were critically reviewed against the standard: "Canva Pro / freelance designer quality, delivered directly to clients via Telegram/WhatsApp on phone screens." Every pipeline failed this bar.

| Pipeline | Benchmark Grade | Core Problem |
|----------|----------------|--------------|
| competitive_analysis | D- | Chart is garbage (describe() data), report is stats homework not competitive intel |
| poster_batch | C- | 75% empty space, no imagery, text crammed top-left |
| content_generate | B- | Copy is decent, PDF is unstyled black-on-white Word doc |
| clone_converge | C | Stopped at 1 iteration, no Jinja2 parameterization |
| tts_generate | F | Empty output directory, silent failure |

Quality gates self-score 8.0 for any non-stub output regardless of actual quality.

### Constraints

- Model: GPT-5.4-mini via OpenAI API, Qwen 3.5 9B via Ollama fallback
- Image generation: fal.ai (FAL_KEY in .env, auto-loaded by adapter/llm_client.py)
- Delivery: Telegram/WhatsApp — outputs must look professional at phone resolution
- Vizier generates all imagery (clients do not provide assets)
- No litellm

### C-Ready Hooks

Each pipeline change includes explicit extension points for Gate C features:
- Client brand config (`config/clients/*.yaml` with accent color, font, tone, logo URL)
- A/B variant generation (produce N variants, score, pick best)
- Human-in-the-loop review queue for sub-threshold outputs

These hooks are documented per-section but NOT implemented in this spec.

## 1. Competitive Analysis Pipeline Rewrite

### Problem

The pipeline is built around `pandas.read_csv()` but real clients provide a *topic* for web research, not a CSV. The LLM-driven operation selector falls back to `describe()`, producing a chart that plots column names on the X-axis with near-zero Y values. The narrative is a statistics textbook summary, not competitive intelligence.

### New Flow

```
topic ("coffee shop competitors in Petaling Jaya")
  |
  v
Step 1: Research query generation (LLM)
  -> 3-5 search queries tailored to the topic
  -> e.g. ["petaling jaya specialty coffee shops", "PJ cafe pricing menu", ...]
  |
  v
Step 2: Web fetch (httpx_fetch, one call per query)
  -> Raw HTML/text from each URL
  -> Truncate to first 10,000 chars per source (httpx_fetch already does this)
  |
  v
Step 3: Data extraction (LLM)
  -> Structured JSON array:
     [{name, location, pricing_range, strengths, weaknesses, differentiator}, ...]
  -> Minimum 3 competitors required, or quality gate fails
  |
  v
Step 4: Chart generation (matplotlib)
  -> Bar chart: pricing comparison across competitors
  -> Second chart (if data supports): feature/rating comparison
  -> Max 3 charts (existing _MAX_CHARTS limit preserved)
  |
  v
Step 5: Narrative report (LLM)
  -> Structured markdown with:
     - Executive summary (market positioning)
     - Competitor profiles (1 paragraph each, citing specific data)
     - Opportunities and recommendations
  -> Must cite specific names, prices, and differentiators from Step 3
  |
  v
Step 6: Assemble report.md with embedded chart image references
```

### Backward Compatibility

The existing `data_path` CSV input path is preserved. When `data_path` is provided, skip Steps 1-2 and feed the CSV directly to the LLM for extraction (Step 3). The web-research path activates only when `data_path` is None.

### Web Research Strategy

Search queries are generated by the LLM, then converted to concrete URLs targeting *structured data sources* (not raw search engines, which return JavaScript-heavy pages unusable via plain HTTP fetch). The LLM generates URLs pointing to:

- **Google Maps / business listing pages** — structured business info
- **Review aggregators** (Yelp, TripAdvisor, Foursquare) — ratings and reviews
- **Industry directories** — business listings with pricing
- **Social media profiles** — public business pages

The prompt:

```
Given the topic "{topic}", generate 3-5 URLs that would contain
competitor information. Target structured data sources like Google Maps
business listings, Yelp pages, industry directories, or social media
business profiles. Return ONLY a JSON array of URL strings.
Do NOT return generic search engine result pages.
Focus on: pricing, location, reviews, unique selling points.
```

Each URL is passed to `httpx_fetch` (the `fetch()` function in `scripts/content/fetch_url.py`). If a fetch fails (timeout, blocked, non-200), skip it and continue with remaining URLs. Minimum 2 successful fetches required to proceed.

**Fallback (< 2 successful fetches):** Run LLM-only analysis where the model generates competitive intelligence from its training data. This produces a lower-quality report (quality score penalized by -2) but still delivers usable output. The report includes a disclaimer: "Based on general knowledge — web research was unavailable."

**Future upgrade path (Gate C):** Replace `httpx_fetch` with a proper search API integration (Brave Search, SerpAPI, or Tavily — Hermes already has Tavily support). This would be a single function swap in the research step, no pipeline restructuring needed.

### Files Changed

- `pipelines/competitive_analysis.py` — rewrite `_pipeline_fn` with web research flow
- `pipelines/competitive_analysis.py` — add `_generate_search_queries()`, `_fetch_and_extract()`, `_extract_competitors()`
- `scripts/content/fetch_url.py` — no changes (already has SSRF protection, 10s timeout)
- `scripts/research/render_chart.py` — no changes (already supports bar/pie/scatter)
- `scripts/research/analyze_data.py` — no changes (still used for CSV path)

### Quality Scoring

| Property | Check | Score impact |
|----------|-------|-------------|
| Named competitors | Report contains >= 3 distinct competitor names | +2 or -2 |
| Numeric citations | Report has >= 5 concrete numbers (prices, ratings, counts) | +1 or -1 |
| Chart validity | Chart has > 2 data points with non-zero, non-identical values | +1 or -2 |
| Report structure | Contains all 3 required sections (summary, profiles, recommendations) | +1 or -1 |

Base score: 5.0. Clamp to [1.0, 10.0].

### C-Ready Hooks

- `client_id` parameter already exists; future client config can inject known competitors, industry vertical, preferred report tone
- Structured competitor JSON output can feed into A/B variant generation for report style

## 2. Poster Batch Pipeline — Two-Layer Composition

### Problem

Posters are text-on-dark-background with 75% empty space. No imagery, no visual hierarchy, no brand personality. The Jinja2 template has minimal CSS with everything left-aligned. For Telegram/WhatsApp delivery, these are unusable.

### New Flow

```
CSV row {headline, body, cta, style_hint}
  |
  v
Step 1: Generate image prompt (LLM)
  -> "warm artisanal coffee shop interior, soft lighting, shallow depth of field"
  -> Derived from style_hint column + headline context
  -> System prompt enforces: no text in image, photography style, suitable as background
  |
  v
Step 2: AI background image (fal_generate)
  -> Explicitly request 800x600 via width=800, height=600 params
  -> fal-ai/flux/schnell model
  -> FAL_KEY loaded from .env (auto-loaded by ensure_env())
  |
  v
Step 3: HTML overlay (redesigned Jinja2 template)
  -> AI image embedded as base64 CSS background-image
  -> Text overlay with semi-transparent dark backdrop for readability
  -> Layout: 3-row CSS grid, vertically centered
     - Row 1 (top third): Headline — large, bold, white, text-shadow
     - Row 2 (center): Body — medium, white, max 2-3 lines
     - Row 3 (bottom third): CTA button — accent color, centered, rounded
  |
  v
Step 4: Playwright screenshot (single pass)
  -> 800x600 viewport, full_page=False
  -> CSS handles text-over-image composition natively
  -> Output: final poster PNG
```

### Background Image Integration

The AI-generated image is base64-encoded and injected as a data URI into the CSS `background-image` property. This happens inside the pipeline before Jinja2 rendering:

```python
image_bytes = Path(ai_image_path).read_bytes()
b64 = base64.b64encode(image_bytes).decode("ascii")
background_image = f"data:image/png;base64,{b64}"
# Pass to template.render(background_image=background_image, ...)
```

Single Playwright pass captures everything — no Pillow compositing needed.

### Fallback (fal.ai unavailable)

If `FAL_KEY` is missing or the API call fails, use a CSS gradient background instead of a flat dark color:

```css
background: linear-gradient(135deg, #1a1a2e 0%, #16213e 50%, #0f3460 100%);
```

The poster still has visual design (gradient + overlay + typography), just without a photo-quality background.

Add optional `style_hint` column to poster CSV schema:

## 4. Clone Converge — Real Iteration + Parameterization

### Problem

Only 1 iteration was rendered. The output is static HTML with no Jinja2 placeholders, defeating the pipeline's purpose of producing *reusable templates*.

### Changes

#### 4.1 Minimum Iteration Enforcement

Add `min_iterations` parameter (default: 2). Even if `composite_score >= threshold` on iteration 1, continue iterating until `min_iterations` is reached. First-pass HTML from vision models is never production-ready.

```python
def run(
    *,
    target_image_path: str,
    output_dir: str = "output/templates",
    max_iterations: int = 5,
    min_iterations: int = 2,       # NEW
    threshold: float = 0.80,
    client_id: str | None = None,
) -> dict[str, Any]:
```

Convergence check becomes:

```python
if score >= threshold and iteration >= min_iterations:
    # Converged
```

#### 4.2 Parameterization Pass

After the convergence loop produces the best HTML, run a final LLM call to parameterize it:

```
Converged HTML
  |
  v
LLM call: "Convert this HTML into a Jinja2 template. Replace:
  - The main heading text with {{ headline }}
  - Body/description text with {{ body }}
  - Call-to-action text with {{ cta }}
  Keep ALL CSS, layout, and structure exactly the same.
  Output ONLY the modified HTML."
  |
  v
Validation: regex check for {{ headline }} and {{ body }}
  -> If missing, retry once with reinforced prompt: "You MUST include {{ headline }}"
  -> If still missing after retry, save unparameterized HTML (quality score penalized by -2)
  |
  v
Parameterized template.html with {{ variables }}
```

#### 4.3 Delta Component Logging

Add structured logging of individual delta components so convergence behavior is observable:

```python
logger.info(
    "Delta components",
    iteration=iteration,
    ssim=delta.ssim_score,
    color_delta_e=delta.color_delta_e,
    pixel_diff_pct=delta.pixel_diff_pct,
    layout_score=delta.layout_score,
    text_match_pct=delta.text_match_pct,
    composite=delta.composite_score,
)
```

### Files Changed

- `pipelines/clone_converge.py` — add `min_iterations`, parameterization pass, delta logging, bump `_PIPELINE_VERSION` to "2.0"

### Quality Scoring

| Property | Check | Score impact |
|----------|-------|-------------|
| Has placeholders | Template contains >= 2 `{{ }}` Jinja2 variables | +2 or -2 |
| Valid HTML | Contains `<html>` and `</html>` tags | pass/fail gate |
| Convergence score | composite > 0.6 | +1 or -1 |
| Multiple iterations | iterations >= 2 | +1 or 0 |

Base score: 5.0. Clamp to [1.0, 10.0].

### C-Ready Hooks

## 6. Honest Quality Scoring System

### Problem

All pipelines self-score 8.0 for non-stub output regardless of actual quality. The quality gate thinks everything is fine when it isn't.

### New Scoring Architecture

Replace hardcoded scores with a property-based scorer per pipeline.

#### 6.1 Scorer Interface

```python
@dataclass(frozen=True)
class QualityProperty:
    """A single measurable quality property."""
    name: str
    passed: bool
    pass_delta: float        # Added to score when passed
    fail_delta: float        # Subtracted from score when failed (always positive)
    detail: str              # Human-readable explanation

@dataclass(frozen=True)
class QualityScore:
    """Composite quality score from property checks."""
    score: float             # Final score [1.0, 10.0]
    passed: bool             # score >= 7.0
    properties: list[QualityProperty]
    pipeline: str
```

#### 6.2 Per-Pipeline Scorer Functions

Each pipeline defines a scorer function that inspects its actual outputs:

```python
def score_competitive_analysis(report: str, chart_paths: list[str]) -> QualityScore: ...
def score_poster_batch(poster_path: str) -> QualityScore: ...
def score_content_generate(content: str, title: str, pdf_path: str | None) -> QualityScore: ...
def score_clone_converge(template_path: str, composite_score: float) -> QualityScore: ...
def score_tts_generate(file_path: str, text_length: int) -> QualityScore: ...
```

#### 6.3 Integration

Each pipeline calls its scorer after producing output, replacing the hardcoded `record_quality(did, 8.0, True)` pattern:

```python
# OLD
quality_score = 6.5 if is_stub else 8.0
record_quality(did, quality_score, not is_stub)

# NEW
score = score_competitive_analysis(report, chart_paths)
record_quality(did, score.score, score.passed)
```

#### 6.4 Scoring Formula

All scorers use the same base algorithm:

1. Start at 5.0
2. For each property: add `pass_delta` if passed, subtract `fail_delta` if failed
3. Properties with `fail_delta = 0` are bonuses — they reward quality but don't penalize absence
4. Pass/fail gate properties: if any gate fails, cap score at 4.0
5. Clamp final score to [1.0, 10.0]
6. `passed = score >= 7.0`

### Files Changed

- New file: `middleware/quality_scorer.py` — `QualityProperty`, `QualityScore` dataclasses, `compute_score()` utility, per-pipeline scorer functions
- `pipelines/competitive_analysis.py` — replace hardcoded score with `score_competitive_analysis()`
- `pipelines/poster_batch.py` — add `score_poster_batch()` call
- `pipelines/content_generate.py` — replace hardcoded score with `score_content_generate()`
- `pipelines/clone_converge.py` — replace hardcoded score with `score_clone_converge()`
- `pipelines/tts_generate.py` — replace L2-only check with `score_tts_generate()`

## 7. .env Auto-Load Robustness

### Problem

`adapter/llm_client.py` auto-loads `.env` from project root at import time. But `scripts/visual/generate_image.py` reads `FAL_KEY` from `os.environ` directly. If called before any pipeline imports `llm_client`, the key won't be loaded.

### Solution

Extract the .env loading logic into a shared utility that any module can import:

```python
# adapter/env_loader.py
"""Load .env file from project root into os.environ. Idempotent."""
import os
from pathlib import Path

_loaded = False

def ensure_env() -> None:
    global _loaded
    if _loaded:
        return
    env_file = Path(__file__).resolve().parent.parent / ".env"
    if env_file.exists():
        for line in env_file.read_text().splitlines():
            line = line.strip()
            if not line or line.startswith("#") or "=" not in line:
                continue
            key, _, value = line.partition("=")
            key = key.strip()
            value = value.strip().strip("'\"")  # Match llm_client.py behavior
            if key and key not in os.environ:
                os.environ[key] = value
    _loaded = True
```

- `adapter/llm_client.py` calls `ensure_env()` instead of inline loading
- `scripts/visual/generate_image.py` calls `ensure_env()` at top of `run()`
- Any future script that needs env vars calls `ensure_env()`

### Files Changed

- New file: `adapter/env_loader.py`
- `adapter/llm_client.py` — replace inline .env loading with `ensure_env()` call
- `scripts/visual/generate_image.py` — add `ensure_env()` call

## 10. Deployment Strategy

Changes ship per-pipeline behind the existing benchmark gate:

1. Implement and test each pipeline independently
2. Run `VIZIER_BENCHMARK=1 pytest tests/benchmarks/test_quality_regression.py -v` after each pipeline
3. Pipeline passes benchmark → merge to master
4. Pipeline fails benchmark → fix before merge

No feature flags needed. The benchmark suite is the gate. Each pipeline is independent — a regression in `poster_batch` does not block shipping `content_generate`.

**Rollback:** If a shipped pipeline degrades in production, `git revert` the pipeline-specific commit. Each pipeline is a single file change (plus scorer integration), so reverts are clean.

| edge-tts or ffmpeg missing in deployment | MEDIUM | HIGH | Upfront dependency check with clear error message |
